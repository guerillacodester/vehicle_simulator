Implemented comprehensive error handling and retry system for telemetry provider
with circuit breaker pattern, exponential backoff, and intelligent recovery strategies.

WHAT
----
- Added RetryStrategy class with circuit breaker (CLOSED/OPEN/HALF_OPEN states)
- Implemented ErrorRecovery with per-error-type recovery actions
- Extended ErrorCodes enum with 4 new error types
- Integrated retry logic into TelemetryDataProvider with metrics tracking
- Created 30 unit tests with 100% passing (RetryStrategy + ErrorRecovery)

- Fixed Jest config to resolve @/ path aliases

WHY
---
- Prevent cascade failures from overwhelming backend services
- Provide intelligent retry with exponential backoff (1s → 30s)
- Automatically recover from transient errors (network, token expiry)
- Track error metrics for monitoring and alerting
- Improve UX with clear error messages and automatic recovery

HOW
---
RetryStrategy:
  - Exponential backoff with 10% jitter to prevent thundering herd
  - Circuit breaker opens after 5 consecutive failures
  - Blocks retry attempts for 60s when OPEN
  - Transitions to HALF_OPEN to test recovery
  - Tracks attempts, failures, and provides statistics

ErrorRecovery:
  - Network errors → auto-retry with backoff
  - Token expired → automatic token refresh
  - Auth failed → require user re-login
  - Server errors → fallback to SSE
  - Parse errors → log and continue (don't disconnect)
  - Classifies errors as transient vs. permanent

TelemetryDataProvider:
  - Integrated RetryStrategy into reconnection logic
  - Tracks comprehensive error metrics (total, by type, recovery rate)
  - Enhanced diagnostics with circuit breaker state
  - Structured error logging with recovery actions
  - Exposes getErrorRecovery() for UI consumption
